2. PROJECT OVERVIEW
--------------------------------------------------------------------------------
Problem Solved: 
Traffic accidents cause severe injuries, property loss, and massive road delays. Predicting accident impact (e.g., congestion distance in miles and severity level on a scale of 1 to 4) based on environmental and weather parameters is crucial for routing engines, insurance adjusters, and emergency service providers.

Why It Matters:
Accurate real-time prediction and preprocessing allow cities to dynamically optimize rescue services, safety alerts, and traffic controls when adverse conditions (high humidity, extreme temperature, low visibility, and high wind speeds) are detected.

Who Are the Intended Users:
Data scientists looking to evaluate tabular preprocessing techniques, road safety researchers, urban traffic engineers, and machine learning students.

System Overview:
The application is a comprehensive modeling suite that processes weather data and builds predictive systems. It has two main presentation mechanisms:
1. Jinja2 Monolithic Dashboard: A Flask backend on port 5004 serving highly polished interactive screens to visualize missing data strategies, coordinate regression equations, examine coefficients shrinkage, and trace Decision Tree splits in real time.
2. Headless API Mode: A decoupled Vite + React Single Page Application (SPA) that acts as a front-end client, pulling data via REST API endpoints served by the Flask application on port 5000.

Architecture & Communication:
- The React client (ports 5173/5000) requests data asynchronously using Axios from the Flask server (`app.py`).
- The server responds with processed JSON payloads (`/api/data-summary`, `/api/eda`, etc.) which the React components render.
- The server-rendered template suite on port 5004 directly fetches cached JSON data (`preprocessing_cache.json`, `models_cache.json`) generated by background scripts (`preprocessing_pipeline.py`, `models_pipeline.py`) to show instantaneous dashboards without re-training models on every reload.

7. MACHINE LEARNING & MODELS EXPLAINED
--------------------------------------------------------------------------------
The project features 10 ML models trained across three classes of estimators:

1. LINEAR REGRESSION (OLS):
   - Supervised Continuous Prediction.
   - Purpose: Predicts congestion `Distance(mi)` based on weather inputs.
   - Intended File: `models_pipeline.py` -> `lin_ols`.
   - Intuition: Fits a hyperplane minimizing the sum of squared residuals.

2. LOGISTIC REGRESSION (OLS, No Penalty):
   - Supervised Classification.
   - Purpose: Classifies accident severity levels (1 to 4).
   - Intended File: `models_pipeline.py` -> `log_ols`.
   - Intuition: Multi-class classification using the cross-entropy loss function.

3. RIDGE REGRESSION (L2 Regularized Linear Model):
   - Adds L2 squared magnitude penalty ($\lambda \sum \beta_j^2$) to limit coefficient size and prevent multicollinearity.

4. LASSO REGRESSION (L1 Regularized Linear Model):
   - Adds L1 absolute magnitude penalty ($\lambda \sum |\beta_j|$) to drive coefficients to exactly zero, performing feature selection.

5. ELASTIC NET (L1 + L2 Hybrid):
   - Blends L1 and L2 penalties, controlled by the mixing parameter `l1_ratio`.

6. RIDGE, LASSO, ELASTIC NET LOGISTIC REGRESSORS:
   - Classification equivalents utilizing the same penalty terms, trained using the SAGA solver to handle multi-class targets.

7. DECISION TREE REGRESSOR:
   - Supervised Regression.
   - Purpose: Non-linear regression path predicting distance.
   - Split Criterion: Mean Squared Error (variance reduction).
   - Hyperparameter: `max_depth=5` to prevent overfitting.

8. DECISION TREE CLASSIFIER:
   - Supervised Classification.
   - Purpose: Classifies accident severity level.
   - Split Criterion: Gini Impurity.
   - Hyperparameter: `max_depth=5`.

8. MACHINE LEARNING MATHEMATICS
--------------------------------------------------------------------------------
Ordinary Least Squares (OLS) Linear Regression:
$$y = X\beta + \varepsilon$$
$$\hat{\beta} = (X^T X)^{-1} X^T y$$

Logistic Regression:
$$P(y=k|x) = \frac{e^{\theta_k^T x}}{\sum_{j=1}^K e^{\theta_j^T x}}$$

Lasso (L1 Regularization):
$$\min_{\beta} \left\{ \frac{1}{2n} \|y - X\beta\|_2^2 + \alpha \|\beta\|_1 \right\}$$

Ridge (L2 Regularization):
$$\min_{\beta} \left\{ \frac{1}{2n} \|y - X\beta\|_2^2 + \alpha \|\beta\|_2^2 \right\}$$

Decision Tree Split Metric (Gini Impurity):
$$I_G(p) = 1 - \sum_{i=1}^J p_i^2$$

9. DATA PREPROCESSING STEPS
--------------------------------------------------------------------------------
1. Imputation comparison: Evaluates listwise deletion against KNN and Median SimpleImputer strategies.
2. IQR Outlier Capping: Caps features at $Q1 - 1.5 \times IQR$ and $Q3 + 1.5 \times IQR$.
3. Nominal Encoding: Maps `Wind_Direction` categories using One-Hot encoding.
4. Ordinal Encoding: Maps twilight categories to 0 and 1.
5. Normalization: Computes scaled features in the range $[0, 1]$ using MinMaxScaler.
6. Standardization: Standardizes features to have mean 0 and variance 1 using StandardScaler.

--------------------------------------------------------------------------------
10. EVALUATION METRICS
--------------------------------------------------------------------------------
- R² (Coefficient of Determination): Proportion of variance explained by regression.
- MSE (Mean Squared Error): Average of squared prediction errors.
- RMSE (Root Mean Squared Error): Standard deviation of residuals.
- Accuracy: Correct classifications / Total records.
- Precision, Recall, F1-Score: Evaluated per class to assess classification quality.

--------------------------------------------------------------------------------
11. ADVANCED FUNCTIONALITY: BOTTOM-UP TREE RENDERING LAYOUT
--------------------------------------------------------------------------------
The visual decision tree in `decision_tree.html` uses a custom bottom-up positioning algorithm to prevent node overlap:
1. `getLeavesCount(node)` and `getMaxDepth(node)` calculate tree dimensions.
2. `assignCoords(node, level)` determines coordinates:
   - Leaf nodes are placed sequentially: `x = xOffset + leafIndex * horizontalSpacing`.
   - Parent nodes are centered above their children: `x = (left_child.x + right_child.x) / 2`.
3. Disjoint subtrees are separated by at least `1 * horizontalSpacing`, preventing horizontal node overlap.
4. Viewport size and connections are scaled dynamically using the SVG viewBox.

12. POSSIBLE INTERVIEW / VIVA QUESTIONS AND ANSWERS
--------------------------------------------------------------------------------
Q: What is the main objective of this project?
A: It is an ML Studio that analyzes traffic accident records to predict accident severity and impact distance based on real-time weather features.

Q: Why are there differences in preprocessing between Linear Regression and Decision Trees?
A: Linear Regression models are sensitive to feature scales and require standardization to ensure balanced gradient descents. Decision Trees partition features using orthogonal splits and are scale-invariant, meaning they do not require scaling.

Q: How did you prevent node overlap in the Decision Tree visualization?
A: We implemented a bottom-up coordinate layout. Leaf nodes are positioned sequentially with a fixed gap, and parent nodes are centered directly above their children. This ensures disjoint subtrees never overlap.
